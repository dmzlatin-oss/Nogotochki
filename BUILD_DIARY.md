# Ноготочки — Дневник сборки

## Обзор проекта

**Название:** Ноготочки — онлайн-запись

**Описание:** Web-сервис для онлайн-записи клиентов на услуги бьюти-студии. Клиенты самостоятельно выбирают услугу, мастера и время; администратор управляет услугами, мастерами, расписанием и записями.

**Дата сборки:** 2026-09-29

**Версия:** 1.0

---

## Технологический стек

### Frontend
- **React 18** — UI-библиотека
- **Vite** — сборщик и dev-сервер
- **TypeScript** — типизация
- **React Router v7** — клиентский роутинг
- **Tailwind CSS** — стилизация
- **react-hook-form + zod** — валидация форм (если использовались)

### Backend
- **Node.js** — runtime
- **Express** — веб-фреймворк
- **better-sqlite3** — работа с SQLite (синхронный драйвер)
- **scrypt** — хеширование паролей
- **jsonwebtoken** (или аналог) — JWT-токены (если использовались)

### База данных
- **SQLite** — встраиваемая реляционная БД
- **WAL-режим** — write-ahead logging для конкурентного доступа
- **SQL-триггеры** — защита от пересечений записей на уровне БД

### Сервер и сеть
- **nginx** — обратный прокси (раздаёт фронтенд и проксирует API)
- **HTTP** — протокол (в development; в prod должен быть HTTPS)
- **Bearer-токены** — аутентификация API

## Как запустить

### Бэкенд

```bash
cd /path/to/nogotochki-booking
PORT=3001 node src/server.js
```

Бэкенд запускается на `http://localhost:3001`.

Переменные окружения:
- `PORT` — порт (по умолчанию 3000, в нашем случае 3001)
- `DATABASE_PATH` — путь к SQLite-файлу (по умолчанию `src/db/booking.db`)

### Фронтенд (development)

```bash
cd frontend
npm install
npm run dev          # Vite на :5173
```

### Фронтенд (production build)

```bash
cd frontend
npm install
npm run build        # Результат в frontend/dist/
```

Собранный `frontend/dist/` раздаётся nginx.

### nginx (production)

nginx конфигурируется так:
- `/nogotochki/` → статика из `frontend/dist/`
- `/nogotochki/api/` → прокси на `http://127.0.0.1:3001/`

## Работа со временем

Салон работает в **Europe/Moscow (UTC+3)**, и клиент может находиться в любом
часовом поясе. Поэтому время нормализовано в трёх слоях:

| Слой | Формат | Пример |
|---|---|---|
| Клиент → сервер | салонское, без суффикса | `2026-10-08T12:00:00` |
| База | честный UTC | `2026-10-08T09:00:00.000Z` |
| Сервер → клиент | московское, с пометкой | `08.10.2026 12:00 МСК` |

Вся конвертация собрана в `src/time.js` (`parseSalonTime`, `toMskDow`,
`dbToMskTime`, `mskDateToUtcStart`). Разбор клиентского времени через
`new Date()` **не используется**: без суффикса JS трактует строку как
локальное время сервера, а сервер работает в TZ=Europe/Moscow, из-за чего
запись уходила на 3 часа назад и не блокировала свой слот.

Сравнение занятости выполняется в миллисекундах, а не сравнением строк:
запись в 02:00 МСК имеет UTC-дату предыдущего дня, и строковое сравнение
давало бы неверный результат на границе суток.

Миграция существующих данных — `migrate-utc.js` (одноразовая).

## API

### Аутентификация

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/api/auth/register` | Регистрация нового клиента |
| POST | `/api/auth/login` | Вход, получение Bearer-токена |
| POST | `/api/auth/logout` | Выход (удаление токена) |
| GET | `/api/auth/me` | Информация о текущем пользователе |

Все токены — Bearer в заголовке `Authorization: Bearer <token>`.

### Услуги

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/services` | Список активных услуг (для клиента) |
| GET | `/api/services/:id` | Информация об услуге |
| GET | `/api/admin/services` | Все услуги (в т.ч. отключённые) — только admin |
| POST | `/api/admin/services` | Создать услугу — только admin |
| PATCH | `/api/admin/services/:id` | Включить/выключить услугу — только admin |

### Мастера

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/masters` | Список активных мастеров с их услугами (для клиента) |
| GET | `/api/masters/:id` | Информация о мастере |
| GET | `/api/admin/masters` | Все мастера (в т.ч. отключённые) — только admin |
| POST | `/api/admin/masters` | Создать мастера — только admin |
| PATCH | `/api/admin/masters/:id` | Включить/выключить мастера — только admin |

### Расписание

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/schedule` | Расписание всех мастеров (с подписью имени) |
| GET | `/api/schedule/:masterId` | Расписание конкретного мастера |
| GET | `/api/admin/schedule` | Все записи расписания — только admin |
| POST | `/api/admin/schedule` | Создать/обновить запись расписания — только admin |
| DELETE | `/api/admin/schedule/:id` | Удалить запись расписания — только admin |

### Исключения из графика (таблица `blocks`)

Разовая незанятость в конкретную дату: обед, отпуск, «в этот день не работает».
Управляется в админке: «Расписание» → «Исключения».

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/blocks` | Все исключения (с именем мастера) |
| GET | `/api/blocks/:masterId` | Исключения конкретного мастера |
| POST | `/api/admin/blocks` | Создать исключение — только admin. Время в салонском формате без суффикса, сервер приводит к UTC |
| DELETE | `/api/admin/blocks/:id` | Удалить исключение — только admin |

### Доступность (п.14 ТЗ)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/masters/:masterId/availability?date=YYYY-MM-DD[&serviceId=N]` | Расчёт свободных слотов для даты и услуги |

Возвращает:
- `slots` — список свободных слотов (ISO-время начала)
- `slotStatuses` — детализация каждого 30-мин интервала: `available`, `busy`, `tooshort`
- `workStart`, `workEnd` — рабочие часы мастера на этот день

### Записи

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/api/bookings` | Создать запись (клиент/мастер/admin) |
| GET | `/api/bookings` | Список записей (клиент — только свои; мастер — свои; admin — все) |
| GET | `/api/bookings/:id` | Конкретная запись (с проверкой прав) |
| DELETE | `/api/bookings/:id` | Отменить запись (клиент — только свою; admin — любую) |
| PATCH | `/api/bookings/:id` | Перенести запись или изменить статус (только admin для статуса) |

### Админ-панель

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/admin/bookings` | Все записи — только admin |
| GET | `/api/admin/users` | Все пользователи — только admin |

## Роли и права

| Роль | Что может |
|------|-----------|
| **client** | Регистрация, вход, выбор услуги/мастера/времени, создание записи, просмотр своих записей, отмена/перенос своей записи |
| **master** | Вход в систему (опционально), просмотр своих записей |
| **admin** | Всё вышеперечисленное + управление услугами, мастерами, расписанием, блокировками, просмотр/отмена/перенос всех записей |

## Основные сценарии использования

### 1. Регистрация нового клиента
1. Клиент нажимает «Зарегистрироваться»
2. Заполняет имя, email, пароль
3. Получает аккаунт

### 2. Вход существующего клиента
1. Вводит email и пароль
2. При успехе попадает на главную, доступен личный кабинет

### 3. Создание записи (полный путь клиента)
1. Выбор услуги (из списка активных)
2. Выбор мастера (из списка активных, умеющих эту услугу)
3. Выбор даты → сервис показывает доступные слоты (учитывает график, длительность услуги, занятость и блокировки)
4. Выбор времени
5. Подтверждение → запись создаётся в БД
6. Запись появляется в личном кабинете

### 4. Отмена записи
1. Клиент открывает личный кабинет
2. Нажимает «Отменить» на активной записи
3. Статус меняется на «Отменена», время снова становится доступным

### 5. Перенос записи
1. Клиент нажимает «Перенести» на своей записи
2. Выбирает новое дату и время
3. Существующая запись обновляется (не создаётся новая)
4. Новое время должно быть свободным

### 6. Работа администратора
1. Вход в админ-панель (`/admin`)
2. Просмотр всех записей
3. Отмена/перенос записей
4. Управление услугами: добавить/редактировать/отключить
5. Управление мастерами: добавить/редактировать/отключить
6. Блокировка времени в расписании (например, обед, отпуск)
7. Все изменения отражаются в клиентской части

### А. Блокировка «обед» — Анна, четверг
- **Дата:** 2026-10-02 (четверг)
- **Мастер:** Анна Ковалева (master_id=1)
- **Услуга:** Маникюр с покрытием гель-лаком (90 мин)
- **Блокировка:** 13:00–14:00
- **Ожидание:** Слоты 12:00–13:30 (30-мин сетка) должны быть `busy`, слот 14:00 должен быть `available`
- **Результат:** ✅

### Б. Личное время — Марина, пятница
- **Дата:** 2026-10-03 (пятница)
- **Мастер:** Марина Орлова (master_id=2)
- **Услуга:** Ламинирование бровей (60 мин)
- **Блокировка:** 15:00–17:00
- **Ожидание:** Слоты 15:00 и 16:00 (60-мин) исключены из `getFreeSlots`, слоты 14:30–16:30 (30-мин сетка) — `busy`
- **Результат:** ✅

### В. Выходной — Елена, суббота
- **Дата:** 2026-10-04 (суббота)
- **Мастер:** Елена Смирнова (master_id=3)
- **Услуга:** Маникюр с покрытием гель-лаком (90 мин)
- **Блокировка:** 10:00–19:00 (весь день)
- **Ожидание:** Все 18 слотов 30-мин сетки — `busy`, ни одного доступного слота
- **Результат:** ✅

### Г. Два клиента — один слот
- **Ситуация:** Два клиента одновременно пытаются занять один свободный слот
- **Ожидание:** Запись первого клиента создаётся, второй получает ошибку `SLOT_UNAVAILABLE`
- **Результат:** ✅

### Д. Конфликт слотов
- **Ситуация:** Клиент выбирает время, которое пересекается с существующей записью или блокировкой
- **Ожидание:** Сервис не показывает занятые слоты; при попытке создать запись — ошибка
- **Результат:** ✅

## Известные ограничения

- Студия работает со вторника по субботу (вторник=2, среда=3, четверг=4, пятница=5, суббота=6), с 10:00 до 20:00
- Воскресенье (0) и понедельник (1) — выходные, мастера не работают
- Без онлайн-оплаты (оплата при посещении)
- Запись без предоплаты
- Один мастер одновременно обслуживает только одного клиента
- Повторный вход по тому же email не создаёт дубликат пользователя
- Пароли хешируются через scrypt (N=16384, r=8, p=1, keylen=64)
- Защита от пересечений: SQL-триггеры + проверка в `createBooking()` с `BEGIN IMMEDIATE`
- Rate limiting на `/api/auth/login` и `/api/auth/register` (5 запросов в минуту)
