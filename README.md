# «Ноготочки» — сервис онлайн-записи в бьюти-студию

Веб-сервис онлайн-записи клиентов к мастерам бьюти-студии «Ноготочки».

**Стек:** Node.js 22 · Express · SQLite (`node:sqlite`) · `crypto.scrypt` для паролей · React 18 + TypeScript + Vite (фронтенд)

## Запуск

```bash
# бэкенд
npm install
cp .env.example .env      # при необходимости
node src/server.js         # порт 3001

# фронтенд
cd frontend
npm install
npm run build               # сборка в frontend/dist
```

Фронтенд раздаётся статикой через nginx по префиксу `/nogotochki/`
(в `vite.config.ts` выставлен `base: '/nogotochki/'`).

## Время

Всё время в интерфейсе — **московское (МСК, UTC+3)**, независимо от часового
пояса пользователя. В базе хранится **честный UTC**; конвертация собрана
в одном месте — `src/time.js`.

| Слой | Формат |
|---|---|
| Клиент отправляет | `2026-10-08T12:00:00` — салонское, без суффикса |
| База хранит | `2026-10-08T09:00:00.000Z` — UTC |
| Интерфейс показывает | `08.10.2026 12:00 МСК` |

Клиент из Новосибирска или Калининграда выбирает и видит московское время —
это подписано явно на странице записи и в карточке.

## Структура

```
src/
  server.js       — маршруты Express, валидация, авторизация по ролям
  time.js         — конвертация MSK ⇄ UTC (единая точка)
  availability.js — расчёт слотов: график − записи − исключения
  bookings.js     — создание/отмена записи, проверка конфликтов
  auth.js         — scrypt-хеши паролей, токены сессий
  middleware.js   — authenticateToken, requireRole
  ratelimit.js    — ограничение частоты запросов
  db/             — подключение SQLite, миграции
frontend/src/
  pages/client/   — витрина, форма записи, «Мои записи»
  pages/admin/    — админ-панель
  components/     — карточки услуг/мастеров, сетка слотов, лента дат
  api/client.ts   — HTTP-клиент
scripts/
  seed-demo.sh        — демо-данные по ТЗ (через API)
  reset-passwords.js  — сброс паролей всех пользователей
migrate-utc.js        — одноразовая миграция записей в UTC
```

## Возможности

### Клиент

- витрина услуг и мастеров
- выбор услуги → мастера → даты → времени
- слоты помечены: свободно / занято (запись или исключение) / не помещается до конца смены
- регистрация и вход, «Мои записи», отмена и перенос своей записи
- клиент не видит чужие записи

### Администратор

- **Записи** — список всех записей, отмена, перенос на другое время
  (форма показывает реальную сетку слотов мастера до переноса)
- **Расписание** — рабочие дни мастеров по дням недели, добавление и удаление дня;
  раздел **«Исключения»** — разовая незанятость в конкретную дату
  (обед, отпуск, «в этот день не работает»), с опцией «весь день»
- **Услуги и мастера** — создание новых мастеров и услуг, включение/выключение,
  связывание мастеров с услугами

## Правила занятости

Слот занят, если выполняется **любое** из условий:

1. в него попадает активная запись;
2. он пересекается с исключением из графика;
3. услуга не помещается до конца рабочего дня мастера.

Проверки идут в миллисекундах, а не сравнением строк, поэтому переход
через полночь и смена часового пояса не создают ложных конфликтов.

## Тестирование

`scripts/seed-demo.sh` создаёт контрольные данные из ТЗ через HTTP API —
это же проверяет серверную валидацию.

Проверено:

- 3 исключения из графика (Анна — четверг 13:00–14:00, Марина — пятница 15:00–17:00,
  Елена — суббота весь день)
- создание записи, конфликт слота, защита от пересечений
- перенос записи, в том числе отказ при попадании в исключение или за пределы смены
- отмена записи
- клиент из другого часового пояса (UTC+7, UTC−7) видит и выбирает московское время
- все дни недели считаются в салонской зоне
