# Ноготочки — сервис онлайн-записи

## Паспорт сервиса

**Название сервиса:** Ноготочки — онлайн-запись

**Цель:** Автоматизировать процесс записи клиентов на услуги бьюти-студии «Ноготочки». Заменить ручную согласование даты и времени визита мастером на самостоятельный выбор клиентом через веб-интерфейс.

**Задачи:**
- Позволить клиентам самостоятельно выбирать услугу, мастера и свободное время
- Автоматически рассчитывать доступные слоты исходя из графика работы мастера, длительности услуги и уже занятых мест
- Предотвращать двойные бронирования одного и того же слота
- Обеспечить администратору инструменты управления услугами, мастерами, расписанием и записями

## Целевая аудитория

- **Клиенты** — посетители студии, которые хотят записаться на услугу
- **Мастера** — сотрудники студии, которые выполняют услуги
- **Администратор** — владелец/менеджер студии, управляет услугами, мастерами, расписанием и записями

## Роли пользователей

| Роль | Возможности |
|------|------------|
| Клиент | Регистрация, вход, выбор услуги/мастера/времени, создание записи, просмотр своих записей, отмена/перенос своей записи |
| Мастер | Вход в систему (опционально) |
| Администратор | Управление услугами и мастерами (добавить/редактировать/отключить), управление расписанием, блокировка времени, просмотр/отмена/перенос всех записей |

## Основные пользовательские сценарии

**Сценарий 1: Регистрация нового клиента**
1. Клиент нажимает «Зарегистрироваться»
2. Заполняет имя, email, пароль
3. Подавляет форму — получает аккаунт

**Сценарий 2: Вход существующего клиента**
1. Вводит email и пароль
2. При успехе попадает на главную, доступен личный кабинет

**Сценарий 3: Создание записи (полный путь клиента)**
1. Выбор услуги (из списка активных)
2. Выбор мастера (из списка активных, умеющих эту услугу)
3. Выбор даты → сервис показывает доступные слоты (учитывает график, длительность услуги, занятость и блокировки)
4. Выбор времени
5. Подтверждение → запись создаётся в БД
6. Запись появляется в личном кабинете

**Сценарий 4: Отмена записи**
1. Клиент открывает личный кабинет
2. Нажимает «Отменить» на активной записи
3. Статус меняется на «Отменена», время снова становится доступным для других клиентов

**Сценарий 5: Перенос записи**
1. Клиент нажимает «Перенести» на своей записи
2. Выбирает новое дату и время
3. Существующая запись обновляется (не создаётся новая)
4. Новое время должно быть свободным

**Сценарий 6: Работа администратора**
1. Вход в админ-панель (`/admin`)
2. Просмотр всех записей
3. Отмена и перенос записей (форма переноса показывает реальные слоты мастера)
4. Управление услугами: создание, отключение
5. Управление мастерами: создание, отключение
6. Расписание работы: рабочие дни по дням недели + раздел «Исключения»
   (разовая незанятость в конкретную дату: обед, отпуск, «в этот день не работает»)
7. Все изменения отражаются в клиентской части

## Функции для клиента

1. **Регистрация** — создание аккаунта с email и паролем
2. **Вход** — вход по email и паролю с созданием токена сессии
3. **Выбор услуги** — просмотр списка услуг с названием, описанием, длительностью и ценой
4. **Выбор мастера** — просмотр мастеров, которые выполняют выбранную услугу
5. **Выбор времени** — выбор даты → показ доступных 30-минутных слотов с учётом графика, длительности услуги, занятости и блокировок
6. **Создание записи** — подтверждение с указанием услуги, мастера, даты и времени
7. **Личный кабинет** — список своих записей со статусами (активна/отменена/завершена)
8. **Отмена записи** — изменяет статус на «отменена», время освобождается
9. **Перенос записи** — изменение времени существующей записи (не создаёт новую)

## Функции для администратора

1. **Управление услугами** — добавить/редактировать/удалить/отключить услугу. Отключённые услуги не показываются при создании новых записей, но сохраняются в информации об уже созданных
2. **Управление мастерами** — добавить/редактировать/удалить/отключить мастера. Отключённые мастера не показываются при создании новых записей, но сохраняются в информации об уже созданных
3. **Управление расписанием** — задать рабочие часы (start/end) для каждого дня недели для каждого мастера
4. **Исключения из графика** — разовая незанятость в конкретную дату и время (обед, отпуск, «в этот день не работает»). Повторяющийся график не меняется
5. **Просмотр всех записей** — список всех записей клиентов
6. **Отмена записей** — отменить любую запись (изменяет статус)
7. **Перенос записей** — изменить время любой записи; форма показывает реальную сетку слотов мастера до переноса

## Сценарии использования

### Сценарий: Конфликт слотов
Клиент выбирает маникюр с покрытием у Анны Ковалевой. Сервис не должен показывать время, которое пересекается с существующей записью (например, запись на 10:00). Также сервис не должен показывать время 13:00–14:00 в четверг (блокировка «обед»).

### Сценарий: Блокировка времени
Клиент выбирает ламинирование бровей у Марины Орловой в пятницу. Время с 15:00 до 17:00 не должно быть доступно, потому что установлена блокировка «личное время».

### Сценарий: Два клиента — один слот
Два клиента одновременно пытаются занять один свободный слот у Елены Смирновой. Запись первого клиента создаётся, второй получает отказ (ошибка конфликта).

## Инструменты и интеграции

- **React 18 + Vite + TypeScript** — фронтенд
- **React Router v7** — роутинг
- **Tailwind CSS** — стили
- **Node.js + Express** — бэкенд
- **SQLite** — база данных (WAL-режим)
- **scrypt** — хеширование паролей
- **Bearer-токены** — авторизация API
- **Rate limiting** — защита от брутфорса
- **SQL-триггеры** — защита от конфликтов слотов на уровне БД

## Ограничения

- Студия работает со вторника по субботу (вторник=2, среда=3, четверг=4, пятница=5, суббота=6), с 10:00 до 20:00
- Воскресенье (0) и понедельник (1) — выходные, мастера не работают
- Без онлайн-оплаты (оплата при посещении)
- Запись без предоплаты
- Один мастер одновременно обслуживает только одного клиента
- Повторный вход по тому же email не создаёт дубликат пользователя

## Возможные риски

- Одновременная запись двух клиентов на один слот (защита: триггер `trg_bookings_no_overlap_insert` + проверка в `createBooking` с `BEGIN IMMEDIATE`)
- Отказ в записи без объяснения причины (защита: после ошибки показываем альтернативные свободные слоты)
- Потеря данных при сбое сервера (защита: SQLite с WAL-режимом, транзакции)
- Несанкционированный доступ к админ-панели (защита: `requireRole('admin')`, `RoleGate`)
- Передача паролей в открытом виде (защита: HTTPS в продакшене, scrypt-хеширование)
- Brute-force атака на форму входа (защита: rate limiting на `/auth/login` и `/auth/register`)
- XSS через имена/описания услуг (защита: React экранирует вывод по умолчанию)
- CSRF через API (защита: авторизация через Bearer-токен, а не cookies; SameSite=Strict для сессионных cookies)
- Invalidated sessions при изменении пароля (не реализовано — потенциальный риск)

## Технические детали

- **Frontend:** React 18 + Vite + TypeScript + React Router v7 + Tailwind CSS
- **Backend:** Node.js + Express + SQLite
- **Авторизация:** Bearer-токены (randomBytes + SHA-256 хеш в БД)
- **Хеширование паролей:** scrypt (N=16384, r=8, p=1, keylen=64)
- **Валидация слотов:** SQL-триггеры `trg_bookings_no_overlap_insert/update` + проверка в коде `createBooking()`
- **Расчёт слотов:** `availability.js` — учитывает график (schedule), длительность услуги (duration_min), занятость (active bookings), исключения (blocks). Все сравнения — в миллисекундах, не строками
- **Время:** в базе честный UTC, в интерфейсе московское (UTC+3) с явной подписью «МСК». Конвертация — `src/time.js`; `new Date()` для разбора клиентского времени не используется
- **API базы:** `/api/services`, `/api/masters`, `/api/masters/:id/availability`, `/api/bookings`, `/api/admin/*`
- **Фронтенд-статика:** собирается Vite, раздаётся nginx по пути `/nogotochki/`
- **API-шлюз:** nginx проксирует `/nogotochki/api/` → `http://127.0.0.1:3001/`

## Пользовательские пути

### Путь клиента
`/ ` → `/login` или `/register` → `/booking` (услуга → мастер → дата → время) → `/confirmation` → `/client`

### Путь администратора
`/login` (вход как admin) → `/admin`

## Структура БД

```
users (id, name, email, password_hash, password_salt, password_params, role, created_at, updated_at)
services (id, name, description, duration_min, price, active)
masters (id, user_id, name, specialization, description, photo_url, work_start, work_end, active)
schedule (id, master_id, day_of_week, work_start, work_end)
master_services (id, master_id, service_id)
bookings (id, client_id, master_id, service_id, start_time, end_time, status, created_by, force_overlap, created_at, updated_at)
blocks (id, master_id, start_time, end_time, reason)
tokens (id, user_id, token_hash, expires_at, created_at)
```
